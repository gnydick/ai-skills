# CLAUDE.md § A ledger mismatch launches a post-mortem agent — full rule

Ruled by Gabe 2026-08-25 (RULE:-dictated): **when an effort's ledger mismatches
between BEFORE and AFTER — a stated assumption that did not hold, an expected
truth that moved, a "should not change" that changed — a SONNET agent is launched
to determine WHY the mismatch happened and what can be learned from it, in a form
new rules can be written from.**

- **The trigger is mechanical, not discretionary.** Any `VIOLATED` verdict in a
  ledger's confirmation pass (§ Every change states its assumptions and its blast
  radius) launches the agent. "I already know why" is not an exemption — the
  explanation that feels obvious at the keyboard is the one that never gets
  written down, and the next effort repeats it.
- **Sonnet, per § Agent cost economy** — this is synthesis and judgement, the tier
  that rule assigns to exactly this work. Serial, per § Serial agents only: it is
  dispatched alone, its RESULT verified, before anything else runs.
- **The output is rule-shaped, not narrative.** The agent answers: what did we
  believe, what was true, WHERE the belief entered (a spec that named two
  consumers when there were three; a commit message asserting neutrality nobody
  checked), and what standing rule would have caught it. A post-mortem that ends
  in "we should be careful" produced nothing.
- **A candidate rule goes through `/rule-intake` like any other** — it is a
  proposal to Gabe, never self-filed by the agent. Rules are adjudicated, and an
  agent does not adjudicate.
- **The mismatch is the asset.** A prediction that failed located a real gap
  between what we designed and what we built; that is worth more than a prediction
  that passed. The agent exists so the gap outlives the campaign.
