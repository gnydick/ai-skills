# Reference sources

What you may do with somebody else's implementation once you have read it.
Loaded at session start.

## Reference only

- Everything you read from someone else's implementation — vendored source, an
  installed dependency you opened to study, code seen on a device, in a
  repository or on the web — is reference only. It is there to show how a
  problem was solved and which edge cases exist.
- Never copy, port, transcribe, translate or paraphrase line by line. Take the
  understanding, then write the implementation from scratch to fit your own
  architecture. The reference is a behavioural contract; the design is yours.
- Citing a reference by file and line to explain a decision is encouraged;
  lifting its code is forbidden. Those citations live in specifications and
  research documents, never in the product's own source.
- This is a standing rule about how the work is done, not caution about
  someone's licence. It holds no matter what the licence permits.
- If a solution seems to require copying, stop and ask rather than deciding for
  yourself that this case is the exception.
